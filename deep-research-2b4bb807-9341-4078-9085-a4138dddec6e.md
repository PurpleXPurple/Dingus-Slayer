## 2. Verified Combat Mechanics

All from `project-slayers.fandom.com/wiki/Features`, cross-checked against the project codebase.

### 2.1 Blocking (validates hover-behind strategy)

- **Directional.** Blocks only protect from the front. Attacks from behind bypass block entirely.
- **Resource-based.** Block bar depletes per blocked hit. Running it to zero → block break → stun.
- **Regenerates** when unblocked and cooldown waits.
- **Weapon durability cost.** Every successful block consumes some weapon durability.
- **Perfect Block window.** Blocking immediately before an incoming hit stuns the attacker.
- **AoE bypass.** High-area attacks hit through block even from behind (positional bypass via splash).
- **Some attacks ignore block entirely** regardless of direction.

**Implication for `attack.lua`:** Hover-behind is a valid strategy against single-target melee bosses. It is *not* universal protection — AoE bosses (Daki, Gyutaro, Akaza) require the retreat/evade systems to remain active. Auto-block should be suppressed while hover-behind is locked, since durability drains for zero benefit.

### 2.2 Combo System (newly discovered — likely root cause of "fights air")

Three exact input patterns confirmed:

- **Air combo:** `L-R-L-R-L`, or hold `Space` while chaining M1/M2
- **Special combo A:** `R-R-L-R-L`
- **Special combo B:** `L-L-R-L-R`

Our current `attack.lua` sends isolated `U.m1()` clicks. The server likely rejects unsequenced M1 spam. This is a **strong candidate** for the "fights air" symptom observed in earlier tests.

### 2.3 Execute Mechanic (G key)

Target below 10 HP enters "knocked" state — 30-second timer, red cross above head, immobilized. Player must be above the target and press `G` to execute. Without execute, the target recovers with partial health.

**Implication:** Our script never uses `G`. Every kill we log as `[Dingus] killed X` is currently verified by target HP reaching zero via damage alone. For sub-10-HP targets, `G` will confirm the kill faster and prevent recovery.

### 2.5 Other Mechanics

- **Perfect Dodge:** Q right before attack → animation blitzes opponent, stuns them
- **Evade Points:** gained on kill or execute, allow leaving PvP server without merit loss
- **Merit System:** gained on kills, lost on death or server leave
- **Daily Spins:** 2 per day, 50% nothing / 12.5% Wen / 12.5% random item / 12.5% BDA spin / 12% clan spin
- **AFK Chamber:** 3 progress bars, timers continue while on play screen, reset on crash or intentional leave

## 4. Implications for the Dingus-Slayer Codebase

Three concrete findings the current script does not account for:

1. **Combo sequencing missing in `attack.lua`.** Isolated M1 clicks likely fail server validation. Fix: sequence `L-R-L-R-L` with proper spacing rather than continuous M1 spam.
2. **Auto-block wastes weapon durability when hover-behind is active.** Fix: suppress `startBlock()` calls while the target is locked behind and within attack range.
3. **Execute mechanic unused.** Fix: add a check for `target.hum.Health < 10` → position above target → `U.tap("G")` to confirm kill.

All three are pure additions to `attack.lua` — no other module needs changes.
